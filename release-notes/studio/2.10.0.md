这一版有三条线。最重的一条在证据：审计一轮运行的那道门，此前有五处可以被这轮运行自己回答——一句写在 here-doc 正文里的 `go test ./...` 就能满足一项从来没跑过的检查。出处从此归宿主所有：事实来自它观察到的东西，不来自执行期可以改写的东西。第二条是远程，那个「连不上」此前只是一句没有码的英文——现在它说得出停在哪一步、以及下一步该做什么，而另一台机器上的文件夹可以直接挑，不必先写进设置。第三条是这条发布线自己：Windows 产物第一次带上 Authenticode 签名。自 2.9.0 起 23 个提交。

## 新增

**出处归宿主所有，动作不能为自己作证**

- 五个洞，同一个修法：事实来自宿主观察到的那件事，而不是执行期可以自由改写的那件事。
- 一句写在 here-doc 正文里的 `go test ./...` 满足了一项从来没跑过的、已声明的项目检查。`commandSegments` 按分隔符切原始文本，于是正文里的那些行也成了段。`SplitOutsideHereDoc` 丢掉正文，留下它旁边的命令。
- 反过来，一个 here-doc 会让整条命令失去分解，于是一轮在它旁边跑了测试的运行读起来像是跳过了测试，而 `python - <<PY` 就此走过了那道拒绝 `python -c` 的 Delivery 门。shell 那几张表现在读的是 permission 早就在读的同一个事实。
- `cd backend && go test ./...` 与根目录那次共用一个身份，于是一次绿的根测试清掉了一次红的子目录测试。规范化现在丢掉拼写和管道，绝不丢掉 check 之前那一段所决定的上下文。
- 一张没有分类的回执把管道的退出码当成了检查自己的，于是 `go test ./... | tail` 可以清掉它正盖着的那次失败。
- `missingMutation` 端到端接好了，却从来没有加过一次。一次证不出来的改动现在是一笔只有观察才结得掉的债；一次事后才跑的检查，说的是状态，不是效果。
- 义务由账本相减导出，从不被宣布：没有任何东西可以发出或抹掉自己的债，而这笔差额跟着造成它的那个结果一起到达模型。Delivery 于是不再拒绝不透明的解释器——宿主审计不了的东西记成未证实并欠着，而不是挡在门外。
- 任务开始时的那些判据是宿主的。声明的检查留着一份当前声明收不回的基线；测试判据在任何可能覆盖它的调用之前从前像里捕获，并通过 `go test -overlay` 对着替换它的代码求值——一个被改写的测试通过了，答的是它自己，不是它替换掉的那些字节。

**连不上的时候，说得出是哪一步、以及下一步做什么**

- 摸到一台机器是那道很少失败的门。冷启动接着要在那边装一个内核，而它停的正是这里——每一次这样的停都以一句没有码的英文抵达，因为 `HostState.Err` 是字符串，而 refusal-path 那道守卫只盯着 `internal/serve`。其中一句让读者去设 `serve_install = npm`，而那不是窗口里有的控件。
- `internal/remote/bootstrap` 现在给「把内核放到那边」的每一种失败法配了 sentinel，按读者会拿它怎么办来分组，而不是按哪个函数产生了它：npm 不在、npm 装在了登录 PATH 之外、本地那个二进制是别的平台的、没有别的可试了、落了地的那个跑不起来、serve 从来没报出端口。`desktop/next` 通过一张表把它们映成点分码，每一句措辞都点名下一步。两个原本匹配错误文本的测试改成匹配身份，那正是让它有身份的意义。
- 主机表单长出那些句子指向的控件：安装策略、跳板机、以及存着口令的那个环境变量。它们本来就存着、本来就在线上、本来就能存过一轮——缺的只有控件，于是让人去改一个，等于让人去编辑 TOML。
- 而一次连接不必再是发现这一切的那个动作。`Probe` 在一次会话里读完首连所依赖的东西，那边什么都不改：是哪台机器、装了什么、npm 跑不跑得起来，以及每条安装路线通不通——不通的那条带着一次真实失败会用的同一个码。`reasonix remote test` 在它已经拨过的那次之后走一遍，窗口里每一行主机都有一个按钮。

**远端的目录可以直接挑，不必先写进设置**（#9475）

- 后端一直收得下任意路径：`/remotes/open` 把 workspace 原样交给 attach，bootstrap 那边解析 `~`、绝对路径和相对 home 的写法。缺的是入口——侧栏能点的行只有主机簿和远端 tree 的并集，于是一个没写下来的文件夹，没有任何办法说出口。
- `attach.Pool.Browse` 只握链路，不握它上面的任何东西：不装 reasonix，不起 serve，不挂转发。挑目录走的是文件协议，所以在一台从没跑过内核的机器上也是秒开的——而那正是要挑目录的那一刻。答完之后连接留着不放，因为往下走一层是第二次调用，中间断掉就要重拨，而一把带口令的私钥会为此再问一次。
- `GET /remotes/{host}/dirs` 只回目录，路径和名字都由那台机器自己写：一台 Windows 主机答给 mac 的是盘符和反斜杠，这边没有一条 filepath 规则切得动它。往上一级同样是它给的值，而不是这边对一套不属于自己的路径语法做的推断。目录太大就截断，并且说出来——一个不吭声的上限，读起来就是「你要找的那个不在」。
- 挑完就打开，打开的同时写进主机簿：远端的 `/tree` 要那边有内核才答得出，冷启动时唯一还记得这个文件夹的就是这一本。记的是**远端答回来的那个路径**，不是输进去的那个——`~` 是在那边展开的，记错一边，主机簿就会为同一个文件夹多列一行。
- 于是列表要有出口：侧栏里每一个「这本簿子写下的」文件夹都能移除，远端那边什么都不动。远端 tree 报来、这边没记过的行不给这个按钮——那是那台机器自己的记录，在这边删掉，下一次读又回来了。
- 设置页里那个盲打路径的输入框旁边也接上了同一个选择器，条件是这一行已经存过：一个还在草稿里的主机没有地址可拨。

**运行带说得出还剩多少可花、还剩多少要做**

- 钱包余额抵达前端已有几个月，而没有任何东西画它；它搭的还是 `GET /status`——一轮在跑的时候，桌面每秒轮询它四次。这个节奏上的一次网络往返，最后是读者在等，所以它现在走自己的路、按自己的节奏答：面板挂载、一轮结束，或者点一下那个标签。四个答案各自分开，而不是折成一个数字。一个没有 `balance_url` 的供应商什么都不画（204）——多数供应商没有，而那里画一道杠，读起来像是一个没加载出来的数字。一个过了保鲜期还站着的值会说自己有多旧。一个读不出来的钱包带着「是哪一种失败」的码，绝不带一个零。
- `internal/billing` 按端点主机挑解码器，和价目表早就在做的一样。Moonshot 的钱包一直是坏的而没有声音：它的响应按 DeepSeek 的形状解析不报错，解出一个空余额，于是一个有钱的账号读回来是不可用。一个不属于任何人的形状现在是 `ErrUnreadable`。
- `Plan.tsx` 和 `panels/Overview.tsx` 根本没有导入者。设计要的那块计划写好了、也上了样式，然后从来没被挂上去，于是计划只活在一张会滚走的工具卡片和一个要切过去的页签里。Plan 回到设计放它的地方，在改动文件旁边；Overview 连同只有它用的那六条翻译一起删掉。
- 两个缺陷对这棵树上此前的每一道检查都是隐形的，所以各配一道守卫。`route_parity` 把 `internal/serve` 的路由对着 `vite.config.ts` 的代理清单核：少一条的那个路由答的是 SPA 外壳，那跟一个坏掉的端点分不出来，而且只在 dev 里发生。`orphan.test.ts` 让一个没有人导入的 `.tsx` 变红。

**这条发布线给自己的 Windows 产物签名**

- Studio 的 Windows 产物按构造就是不签名的：生产的 SignPath 策略只信任一个来源——受保护的 `main-v2`——所以这条分支上的构建请不到那张证书。工作流写明了这一点，然后就停在那儿。而在一台受管的 Windows 端点上，这不是一句 SmartScreen 警告：安装器在 `CreateProcess` 就被拒，Windows 报的是「无法访问指定的设备、路径或文件」，读起来像权限问题，而它不是。
- 桌面线那套机制整套搬过来，按 Studio 实际发的东西改。签名分两段，理由 `main-v2` 已经写过：只签最后那个 NSIS 容器，装完之后留在盘上的 `reasonix-studio.exe` 仍然没签名，而那恰恰是信誉与 ML 启发式会隔离的东西。所以可执行文件在还是一个散文件的时候先签，包围着这批确切的字节重建，容器第二个签——由 artifact configuration 去核实载荷的签名，而不是信任这个工作流的顺序。
- `studio-build.sh` 长出让这件事成为可能的那道缝：`--windows-payload` 造出用户真正运行的东西然后停，`--windows-package` 从交给它的载荷目录造 zip 和安装器。一次性的平台路径把两者组合起来，所以一次不签名的构建、以及一次维护者本地的运行，与此前逐字节相同。
- `.signpath/` 带着这条线自己的契约——分支 `studio`、工作流 `release-studio.yml`——`cmd/signpath-contract` 在任何东西被构建之前验证并取指纹，于是一处被放宽的来源是在门上失败，而不是在签名请求上。它的分支钉死成 `studio`，而不是从它检查的那个文件里读：一道从自己的审查对象里读出自己答案的守卫，守不住。
- 光有 token 还不够。`SIGNPATH_API_TOKEN` 是仓库级 secret，本来就读得到，于是只凭它，这个文件一合并就会打开签名，而策略此时仍然只信任 `main-v2`——下一个 tag 就会栽在一张还给不出来的签名上。`STUDIO_SIGNING_ENABLED` 是没有任何 secret 表达得了的那一半：SignPath 的控制台已经被告知信任这条线的来源。在它被置上之前，合并是惰性的。
- `scripts/verify-windows-authenticode.ps1` 来自已退役的桌面线，而且描述的还是它：载荷根目录下六个可执行文件、一个带 `current.json` 和 `versions/vX.Y.Z/` 的便携包，以及一个 studio 工作流从来没传过的必填 `-PortableArchivePath`。Studio 只发一个可执行文件。这一步挡在 `HAS_SIGNPATH` 后面，而它从来没有为真过，所以没有东西跑过它——把门打开，会先签好两个产物，然后栽在那道本该确认签名的验证上。它现在核的是 Studio 实际发的东西：载荷里那一个可执行文件、包在它外面的安装器，以及便携 zip 里的那份副本——那份副本按哈希与已签名的载荷比对，因为光核签名会放过一个用更早的、同样签过名的构建打出来的包。在一台真的 Windows 机器上核过三种情形：三个产物都已签名且相互吻合是通过，一个装着另一份已签名二进制的压缩包按「对不上」被拒，一个没签名的载荷按「缺签名」被拒。

## 修复

- **看不见的那道流光不再烧 CPU**（#9481）。输入框边框上那道「跑起来时沿边框走
  的光」写着「停下就必须熄灭」，而熄灭的只有 opacity：`.glowring` 变透明，里面
  那个 150px 的径向渐变照旧沿 `offset-path` 每秒 60 次绕圈，在一层
  `mask-composite: exclude` 里重新光栅化——从窗口打开到关掉，一刻没停。
  `offset-distance` 不走合成器，所以这笔账全落在主线程上：一条 400 轮的会话、
  什么都没在跑的窗口，主线程 44%，渲染进程 1.11 核；把它摘掉是 11.4% 和 1.02 核。
  报上来的正是这个形状——「webview2 占 50%，关掉软件立刻回到 1% 以下」。
  修法是让动画和它的可见性走同一个条件：默认 `animation-play-state: paused`，
  只有 `.pane[data-run="running"]` 把它放开。闲置 44.0% → 11.4%（降频 4x）、
  9.8% → 2.9%（不降频）；正在跑的那一档不变，那时它本来就该在走。让那一半更便宜
  的几次尝试（步进时序、图层提升、更小的光斑）跨运行都复现不出来，于是一个都没采。
- **并行的工具调用不再同时写同一份基线**。每一个调用结束时都会问这一轮欠着什么，而那个问句里藏着一次写：任务第一次被问到时，才捕获它此后一直要被对照的那份检查基线。于是一批并行工具在各自完成的那一刻同时到达这次捕获，`-race` 在 `checkContract` 上报出读写竞争——一个能让两份基线互相覆盖的窗口，而基线正是判定这一轮交付是否成立的东西。捕获移到一轮的开头，那里没有别的东西在跑，问句于是成了纯读取。这也更贴合它自己的道理：基线要取自任何调用都还没能改写声明之前的那个前像。
- **同一个检查换一层外壳仍是同一项**。验证身份保留了检查之前的每一段，于是 `cd /w && ls -la && go test ./...` 和 `cd /w && go test ./...` 成了两项，谁也不会取代谁——而一个刚跑绿的检查，本该盖掉它上一次读不出结果的那回。身份现在只留决定「在哪里、在什么之下跑」的那些段（`cd`、`export`、赋值），把站在旁边的列目录和看状态丢掉。
- **一个连不上的外部服务是一行，不是一次告警**。外部服务那一块是运行带上唯一被画成红色的东西：左边一道内嵌的竖线，下面用 `--err` 排着端点的整句抱怨。一列灰色读数里的三行红，读起来像一个卡在仪表盘里的对话框。运行带对这件事本来就有规矩，写在 `.drow` 的调子里：带着「这里坏了」的那个标记拿颜色，描述它的那些字不拿。圆点仍是红的，标题里的计数仍然说有几个；那道竖线是同一件事的第三种说法，而原因现在用的是运行带上每一条次要行都在用的字号和字重。
- **shell 路由 `/balance`，而 `make test` 走到每一个模块**。把钱包拆到自己的路由上时，调用加进了 `sse.ts`，`apiPaths` 被落下了，于是请求穿过去落到静态资源上，运行带读回一个 404。路由 parity 测试抓到了它，而且此后一直是红的——红在一个根目录 `go test ./...` 看不见的嵌套模块里，那正是一个红测试藏得最久的地方。`make test` 现在也跑 shell 和 SDK。
- **只有工作区已经不再持有的判据才值一次构建**。基线求值在每一轮结束时按捕获的判据各跑一次工具链。一次范围大的改动会把树里每一个测试文件都捕获下来，于是一轮一个都没重写的运行仍然为每个文件付掉一次构建——模型已经答完，窗口在转，而宿主在悄悄地构建。一个工作区仍然逐字节持有的判据，项目自己的检查已经跑过它了；overlay 存在，是为了那些它已经不再持有的。没有变的判据现在不产生事实、也不产生构建，而第一次真的要跑的求值会宣布自己进入了检查阶段，不再留下一段没有解释的等待。

## 内部

- 能力端口是六个端口，不是一个。Capabilities 在一个接口里点了 56 个方法——skills、hooks、MCP、网络、shell、权限、沙箱、配置修复、扩展 UI、供应商目录。驱动端口的全部意义就是一个前端只看见它驱动的东西，而这一个接口把它抵销了：一个列 skills 的面板，连同它们一起拿到了 `SavePermissionRules` 和 `SaveSandboxSettings`。它按前端本来就在用的那几条线拆开：`SlashDispatch`、`Skills`、`Hooks`、`MCPControl`、`RuntimeSettings`、`Extensions`；`CapabilityScope` 搬到 `Lifecycle`，它描述的那个工作区本来就住在那里。这一拆暴露出来的是 ACP——`EditorAPI` 嵌了整个面，于是这个传输够得到它从来没调用过的 skill 编写、hook 编辑和沙箱规则。它现在点名自己驱动的那三个端口，隔离守卫给它的未用计数从 3 变成 0。没有任何实现改变。
- 一轮的形状是一个值，不是一个方法名。一次 turn 请求有六个正交的部分——输入、带着 @-ref 的那一行、显示文本、编辑前的原文、resolver、输出格式——外加一个 sync/guarded 开关。它们此前被拼成 40 个入口方法：`runRefTurnWithRefsFormat`、`runScopedRefTurnWithFormat`、`runTurnLoopWithFrozenImagesRawDisplay`，沿着这个笛卡尔积一路排下去；而在它们之间挑选的那个分支，是在两条 if 里对三个变量赋闭包，那是一张写成控制流的数据表。审批是同一个形状的小号版本。两者都塌回一个值，剩下 27 个入口方法，端口保持它公开的形状：没有任何前端契约移动过。
- 塌掉这一层找到了一个 bug。`runEditedGoalLoopWithImageRefsRawDisplay` 是 `runTurnLoopWithPreparedTurn` 的一份拷贝，而当 e4e6936b1 教会一轮去做完它欠下的事、而不是弹一张只写着「继续」的卡片时，它只教了两者之一。一次重新提交的编辑，在还差着验证就结束时，仍然拿到那张卡片。拷贝没有了，编辑骑同一个循环；`TestEditedResubmitFinishesWhatItOwes` 在没有这个修复时是红的。还剩一处不对称，是原样留着而不是盲修的：`turnLoopRunner` 的编辑分支仍然不绑定这一轮的输出格式，而普通分支绑定。
- 临时目录会重试它的清理，因为 Windows 可能还攥着那个文件。`t.TempDir` 只删一次目录，而在 Windows 上一个被删掉的文件会保留它的目录项直到最后一个句柄关闭——于是一个在系统仍握着它写过的东西时就结束的测试，会在每个文件都已经没了的情况下，因为「非空」而删除失败。实测约 2% 的会话保存会撞上，且总是在 10ms 以内。`testenv.TempDir` 是一个就地替换，它的清理会重试 `RemoveAll`，并把那个始终不放的记进日志，而不是让测试失败。desktop 模块导入不了它，所以它那 15 个文件保留 `t.TempDir`。
- 词表守卫此前一直是红的，红的是它自己。中文是合法的 JS 标识符，`en_storage.ts`
  里写的是 `占用: "Space used"`，而 `perf/i18n.mjs` 只认 `"占用": "…"` 那种带引号
  的写法——存储面板那六条于是被报成「缺英文翻译」，它们其实一条不少。修好之后它
  读出 1276 个键，与 `Object.keys(EN).length` 一字不差。同时它开始报「这一行我读
  不出键来」并让退出码变红：一个读源码文本的守卫，必须说得出自己哪里没读懂，否则
  下一种写法还是会被当成缺翻译。一道永远红的门和一道永远绿的门是同一种失败——它
  已经不再谈论它的审查对象，只在谈论它自己。
- perf 多了 `idle.mjs`：**看不见的东西不许动，闲着的窗口不许烧 CPU**。判据里此前
  没有「闲置」这一档，于是一条永远在跑的装饰动画躺了整整一版没人发现。两条断言，
  一条读结构一条读开销：在跑的动画，它的元素必须真的看得见（opacity 为 0、
  visibility 不可见、盒子没面积，机器再快也是错的）；以及动画在闲置窗口上的净
  开销——同一台机器把动画全关再量一遍，两者相减——要在预算以内，机器快慢在相减
  里抵消。那道流光的两头都断言：跑起来时它要真的在走，否则把它焊死成永不动也是
  绿的。`selfcheck.mjs` 收下它。
- acp 那 31 处等待改用早就写好的 budget。`rpcCallBudget` 的注释里已经写明了这个失败——「它是挂起探测器，不是延迟断言……此前那两秒，在整棵树同时被测的时候就会失败」——但它只被用在一个调用点，其余 31 处仍是字面量的两秒。它们是同一件事：每一处都以「从来没启动」「从来没被调用」「等超时了」失败，没有一处是在等着确认某件事不发生，所以没有一处想要一个短的期限。一个提前触发的等待，报的是一次并没有发生的挂起——而机器只是忙。
- `ask` 到用户之间那根线现在被一个测试拽着。它只有一条：`EnableInteractiveApproval` 装在执行器上的那个 Asker——而在此之前，整棵树里没有任何东西断言过这根线是活的。断了的话，每一个提问都会拿到无人应答时的那句「模型自行假设」的回退：一次本该问人的运行，替用户把决定做了，而没有任何一道门会吭声（#9509）。两个方向都钉住：接上审批的控制器必须真的把问题递出去并收回答案，而一个没有接的必须回那句回退、且不许凭空发出一个没人能答的提问。
- wire-parity 收下 `port/remote.ts`：`RemoteHostView`、`RemoteListing`、`RemoteFolder` 与桌面那三份手抄的副本被声明成对子。`RemoteHostEdit` 故意不在里面——内核仍然收旧行那个单数的 `workspace`，而写它的那个页面是有意只送列表；那是一个前端没填满的请求，不是一张它读不到的图。
