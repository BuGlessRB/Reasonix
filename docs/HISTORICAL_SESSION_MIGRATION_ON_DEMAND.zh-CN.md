# 历史会话按需迁移

## 范围

Desktop 启动不再转换所有旧版 transcript 或 canonical v4 目录。启动阶段
只恢复少量、非历史会话的生命周期保留记录。历史目录只读取目录项和持久化
账本；用户打开某一行时才发起明确的导入。

## 所有权与生命周期

- 导入获取按源隔离的跨进程锁；canonical 源在完整复制和提交期间持有共享目录
  所有权锁。
- 如果源正在被其他 CLI 或 runtime 使用，立即显示阻塞状态，不会排队等待
  Desktop runtime rebuild 锁。
- 同一源的重复请求加入同一个进程内调用。
- 批量导入按顺序执行，支持取消和继续。取消会保留 `prepared`、
  `content_ready` 保留记录，下一次显式请求可以继续。
- 已有 `content_ready` 的操作直接基于持久化目标重放，不会再次转换成第二个会话。
- 归档和删除状态具有最终权威性；目录重新扫描不会让会话复活。

## 兼容性

源文件保持不变。已有 source mapping、恢复记录、未知字段、展示信息和保留
产物都会保留。旧版按路径打开的入口仍是当前 DAG head 的别名；有效的 head
索引会把其他 head 暴露为独立的按需源，但列目录时不会重放事件日志。

## 验证

已加入启动不迁移、跨进程冷导出争用、重复请求与取消、prepared/content_ready
恢复、归档/删除隔离，以及列表、重试、提交后打开和批量控制的真实浏览器交互测试。
